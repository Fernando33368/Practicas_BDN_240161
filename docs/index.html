Origen y cobertura
    
  
    Reglas de clasificación aplicadas
    
  
      
   
    • Monovalor / multivalor: cada columna SQL almacena un único valor por fila (monovalor). No se encontraron columnas declaradas como arreglos o listas multivalor. Los campos TEXT no se consideran multivalor sin una regla explícita en el DDL.
      • 
   
    • Almacenado / derivado: las columnas de tablas se clasifican como almacenadas físicamente. Los resultados de vistas son derivados al consultarse. Un importe como subtotal se mantiene como almacenado porque el respaldo lo define como columna, aunque pueda calcularse desde otros valores.
      • 
   
    • Naturaleza: identificadores se clasifican como cualitativos nominales aunque sean numéricos; cantidades e importes como cuantitativos; fechas como temporales; estados enumerados como cualitativos nominales o binarios.
      • 
   
    • Composición formal: se expresa mediante el tipo MySQL y su precisión/longitud, por ejemplo DECIMAL(12,2), VARCHAR(80), BIT(1) o el conjunto literal de valores de ENUM.
      • 
   
    • Dominio: se obtiene de restricciones del tipo (longitud, precisión, signo, valores ENUM, BIT). Si el SQL no define un rango de negocio mediante CHECK u otra restricción, no se inventa.
      • 
   
    • Obligatorio / opcional: NOT NULL = obligatorio; columna nullable = opcional. Un valor DEFAULT no convierte por sí solo una columna nullable en obligatoria.
      • 
  
    
  
    Clasificación aplicada: se clasifica cada columna según su naturaleza, multiplicidad, persistencia, obligatoriedad, función como clave y dominio. No se atribuye al respaldo una taxonomía externa que no esté definida en el SQL.
